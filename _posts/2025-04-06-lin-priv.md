# I Just Got a Low-Priv Shell!

> **What would brxzyy do right now?**
>
> A practical Linux post-exploitation and privilege-escalation checklist for authorized CTFs, labs, and penetration tests.

---

## 1. Stabilize the Shell

Try Python first:

```bash
python -c 'import pty; pty.spawn("/bin/bash")'
```

Or Python 3:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

Set a useful environment:

```bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/tmp
export TERM=xterm-256color
alias ll='ls -lsaht --color=auto'
```

Background the process:

```text
Ctrl + Z
```

Then:

```bash
stty raw -echo ; fg ; reset
stty columns 200 rows 200
```

# 2. Various Capabilities?

Before doing anything complicated, find out what tools are available:

```bash
which gcc
which cc
which python
which python3
which perl
which wget
which curl
which fetch
which nc
which ncat
which nc.traditional
which socat
```

These tell you what you can use for:

* File transfer
* Scripting
* Compilation
* Networking
* Shell stabilization

# 3. Compilation? Very Back Burner

Compilation should generally be a fallback.

First understand the target:

```bash
file /bin/bash
uname -a
cat /etc/*-release
cat /etc/issue
```

# 7. Are We a Real User?

Start with:

```bash
whoami
id
groups
```

Then:

```bash
sudo -l
```

Inspect sudo configuration:

```bash
ls -lsaht /etc/sudoers
ls -lsaht /etc/sudoers.d/
```

If `sudo -l` reveals unusual permissions, investigate that before moving on.

---

# 8. Are Any Users a Member of Exotic Groups?

For the current user:

```bash
groups
```

For a particular user:

```bash
groups <user>
```

Or:

```bash
id <user>
```

Also inspect:

```bash
cat /etc/group
```

Pay attention to groups that can provide access to privileged resources or services.

# 9. Check Out Your Shell's Environment Variables

```bash
env
```

Check PATH:

```bash
echo "$PATH"
```

PATH-related privilege escalation:

https://www.hackingarticles.in/linux-privilege-escalation-using-path-variable/

The important question is:

> Does a privileged process execute commands through PATH, and can the current user influence the directories being searched?

# 10. Users?

Inspect `/home`:

```bash
cd /home/
ls -lsaht
```

List local users:

```bash
cat /etc/passwd
```

Look for:

* Interesting usernames
* Service accounts
* Home directories
* Unusual login shells

# 11. Web Configs Containing Credentials?

If the target hosts a web application:

```bash
cd /var/www/html/
ls -lsaht
```

Inspect the entire web directory:

```bash
find /var/www -type f 2>/dev/null
```

Search for credentials:

```bash
grep -RniE 'password|passwd|secret|token|username|credential' \
    /var/www 2>/dev/null
```

Look for:

```text
config.php
.env
settings.py
database.yml
application.properties
*.conf
*.ini
*.bak
```

Credentials discovered here may be reusable against:

* SSH
* Databases
* Internal services
* Other local accounts

# 12. SUID Binaries

Search for SUID binaries:

```bash
find / -perm -u=s -type f 2>/dev/null
```

For anything interesting:

```bash
ls -la <binary>
file <binary>
```

Look for:

* Custom binaries
* Unexpected locations
* Recently created binaries
* Binaries owned by privileged users

GTFOBins:

https://gtfobins.github.io/

---

# 13. SGID Binaries

Search for SGID binaries:

```bash
find / -perm -g=s -type f 2>/dev/null
```

Again, focus on unusual binaries rather than assuming every SGID binary is exploitable.

GTFOBins:

https://gtfobins.github.io/

# 15. Binary / Language Capabilities

Check file capabilities:

```bash
getcap -r / 2>/dev/null
```

Reference:

https://www.insecure.ws/linux/getcap_setcap.html#getcap-setcap-and-file-capabilities

Pay particular attention to unusual capabilities such as:

```text
cap_setuid
cap_dac_override
cap_dac_read_search
cap_sys_admin
```

The important question is:

> Is there an executable with a useful capability that the current user can run?

# 16. Start Monitoring the System

The question becomes:

> **"shxtterme... Is privilege escalation going to come from some I/O file operation being done by a script on the system?"**

A static process listing only shows what is happening right now.

PSpy can reveal commands executed periodically.

PSpy:

https://github.com/DominicBreuker/pspy

Move to a writable directory:

```bash
cd /var/tmp/
```

Transfer the appropriate binary:

```text
pspy32
pspy64
```

Make it executable:

```bash
chmod 755 pspy64
```

Run:

```bash
./pspy64
```

Look for:

```text
root → script
root → backup
root → tar
root → cp
root → mv
root → python
root → custom binary
```

Especially interesting:

```text
root executes /path/to/script.sh
```

when the current user can modify:

```text
/path/to/script.sh
```

# 17. What Does the Local Network Look Like?

Try:

```bash
netstat -antup
```

Listening services:

```bash
netstat -tunlp
```

If `netstat` is unavailable:

```bash
ss -tunlp
```

Look for services bound to:

```text
127.0.0.1
```

A service listening only on localhost may not have appeared during the external port scan.

---

# 18. Is Anything Vulnerable Running as Root?

Start with:

```bash
ps aux | grep -i 'root' --color=auto
```

Also inspect everything:

```bash
ps aux
```

Look for:

* Root-owned scripts
* Custom applications
* Databases
* Monitoring software
* Backup jobs
* Services running from unusual paths
* Processes accessing writable files

---

# 19. MySQL Credentials / Root Unauthorized Access?

Check whether MySQL exists:

```bash
which mysql
```

Check whether it is listening:

```bash
ss -lntp | grep 3306
```

If authorized credentials are available:

```bash
mysql -uroot -p
```

Credential-reuse candidates may include credentials discovered during enumeration.

For example:

```text
root : root
root : toor
root : <blank>
```

Do not blindly brute-force credentials. Prefer credentials found in application configuration, backups, or user files.

# 21. SSH Keys

Quick look:

```bash
ls -lsaR /home/
```

Search specifically:

```bash
find /home -type f \
    \( -name "id_rsa" -o -name "id_ed25519" -o -name "authorized_keys" \) \
    2>/dev/null
```

Also inspect:

```text
.ssh/
id_rsa
id_ed25519
authorized_keys
known_hosts
```

SSH keys can potentially enable lateral movement to another account.

# 25. Temporary Directories

```bash
ls -lsaht /tmp/
ls -lsaht /var/tmp/
ls -lsaht /dev/shm/
```

Check permissions:

```bash
ls -ld /tmp /var/tmp /dev/shm
```

Writable temporary directories are not automatically vulnerable.

The interesting situation is:

```text
low-privileged user
        ↓
writes / modifies file
        ↓
privileged process consumes file
        ↓
privilege boundary crossed
```

# 27. NFS

Check:

```bash
cat /etc/exports
```

Look for:

```text
no_root_squash
```

From the attacking machine:

```bash
showmount -e <TARGET>
```

NFS reference:

https://recipeforroot.com/attacking-nfs-shares/

A weak NFS configuration may allow unauthorized manipulation of files on an exported filesystem.

# 28. Where Can I Live?

Common writable locations:

```bash
/tmp/
/var/tmp/
/dev/shm/
```

Check:

```bash
ls -ld /tmp/
ls -ld /var/tmp/
ls -ld /dev/shm/
```

Search for writable files:

```bash
find / -writable -type f 2>/dev/null
```

A targeted search is often faster:

```bash
find /etc /opt /var/www /usr/local \
    -writable -type f 2>/dev/null
```

# 30. Forwarding Out a Weak Local Service

Sometimes a service is only available on:

```text
127.0.0.1
```

If it is interesting, authorized port forwarding can expose it for investigation.

Meterpreter reference:

https://www.offensive-security.com/metasploit-unleashed/portfwd/

Conceptually:

```text
Attacking Machine
        │
        │ Port Forward
        ▼
Target 127.0.0.1:<PORT>
        │
        ▼
Internal Service
```

The fact that a service is old does **not** automatically mean it is exploitable. Confirm the actual version and vulnerability.

# 31. `/etc/passwd` Permissions

Check:

```bash
ls -la /etc/passwd
```

A low-privileged user normally should not be able to modify `/etc/passwd`.

If a lab intentionally makes it writable, that represents a serious privilege-boundary misconfiguration.

The important observation is:

```text
Can my current user modify a file that controls local account identity?
```

# 32. Cron

Current user's cron:

```bash
crontab -l
```

If permitted:

```bash
crontab -u root -l
```

System-wide cron:

```bash
cat /etc/crontab
ls /etc/cron.*
```

Look for unusual system-wide jobs.

Particularly interesting:

```text
root → executes script
```

where the script is:

```text
writable by current user
```

* Scripts
* Configuration
* Backups
* SSH keys
* Application files
* Custom binaries

# 35. Shell History

Check readable history files:

```bash
find /home -maxdepth 3 -type f \
    \( -name ".bash_history" -o -name ".zsh_history" \) \
    -readable 2>/dev/null
```

If permitted, inspect relevant histories:

```bash
cat /home/<user>/.bash_history
```

Look for commands containing:

```text
ssh
mysql
passwords
tokens
API keys
backup commands
```

# 36. Credential Hunting

Search application directories:

```bash
grep -RniE 'password|passwd|secret|token|api[_-]?key|credential' \
    /home /opt /var/www 2>/dev/null
```

Look for backups:

```bash
find /home /opt /var/www -type f \
    \( -name "*.bak" -o -name "*.old" -o -name "*.backup" \) \
    2>/dev/null
```

# 37. File Ownership

When something looks interesting:

```bash
ls -la <file>
```

Then:

```bash
stat <file>
```

Ask:

```text
Who owns it?
Who can write it?
Who executes it?
When was it modified?
Where is it executed from?
```

# 38. Writable Scripts

Search common application directories:

```bash
find /opt /usr/local /var/www /etc \
    -type f -writable 2>/dev/null
```

A writable script is particularly interesting if:

```text
root
 ↓
executes script
```

and:

```text
current user
 ↓
can modify script
```

# 39. PATH-Based Privilege Escalation

Check:

```bash
echo "$PATH"
```

Then investigate privileged scripts.

For example, if a root-owned script contains:

```bash
backup
```

instead of:

```bash
/usr/bin/backup
```

PATH resolution may become relevant if the execution environment can be influenced.

Reference:

https://www.hackingarticles.in/linux-privilege-escalation-using-path-variable/

# 45. Kernel Exploitation — Last Resort

Check:

```bash
uname -a
cat /etc/os-release
```

Kernel exploitation should generally come after checking:

```text
sudo
SUID
SGID
capabilities
cron
credentials
SSH keys
writable files
local services
interesting groups
```

A simple misconfiguration is usually preferable to a kernel exploit.

---

# 46. The shxtterme Mindset

Don't just blindly execute commands.

For every interesting result, ask:

### Who am I?

```bash
whoami
id
```

### What is privileged?

```bash
ps aux
sudo -l
```

### What is unusual?

```text
SUID
SGID
capabilities
custom binaries
custom scripts
localhost services
unusual groups
```

### What does root execute?

```bash
ps aux
./pspy64
```

### What can I modify?

```text
files
scripts
directories
environment
PATH
configuration
temporary files
```

### Can I influence a privileged operation?

That is the key question.
