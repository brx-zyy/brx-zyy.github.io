# AWS Key Concepts & Terminology

Amazon Web Services (AWS) is a cloud platform that lets you run servers, store files, manage databases, build applications, and handle networking without having to manage physical hardware yourself. Everything can be managed through the AWS Console, CLI, or APIs

---

## AWS Global Infrastructure

AWS infrastructure is organized into:

```text
AWS
│
├── Regions
│   └── Availability Zones
│       └── Data Centers
│
└── Edge Locations
```

### Region

A **Region** is a geographic area containing multiple isolated Availability Zones.

Examples:

```text
us-east-1
eu-west-1
ap-south-1
```

Regions are independent from one another and are commonly selected based on:

* Latency
* Data residency
* Availability
* Compliance
* Service availability
* Cost

### Availability Zone

An **Availability Zone (AZ)** is an isolated location within an AWS Region.

A Region normally contains multiple AZs.

Example:

```text
Region
│
├── AZ-Riko
├── AZ-Miko
└── AZ-Niko
```

Using multiple AZs improves availability and fault tolerance.

### Edge Location

An **Edge Location** is an AWS location used by services such as CloudFront to deliver content closer to users.

# AWS Accounts

An AWS account provides an isolated environment for AWS resources.

A typical environment may contain:

```text
AWS Organization
│
├── Security Account
├── Logging Account
├── Development Account
├── Testing Account
└── Production Account
```

AWS accounts can be managed together using **AWS Organizations**.

---

## AWS Organizations

AWS Organizations allows multiple AWS accounts to be centrally managed.

Important concepts include:

```text
Organization
│
├── Management Account
│
├── Organizational Units
│   ├── Security
│   ├── Development
│   └── Production
│
└── Member Accounts
```

### Service Control Policies

**SCPs** define the maximum permissions available to accounts or organizational units.

An SCP does not directly grant permissions.

# IAM

**AWS Identity and Access Management (IAM)** controls authentication and authorization in AWS.

IAM is one of the most important AWS security services.

```text
Identity
   ↓
Authentication
   ↓
Authorization
   ↓
AWS Resource
```

IAM manages:

* Users
* Groups
* Roles
* Policies
* Permissions
* Access keys

---

## IAM Users

An IAM user represents an identity within an AWS account.

A user can have:

* Console credentials
* Access keys
* IAM policies

Example:

```text
Riko
 ↓
IAM User
 ↓
Permissions
 ↓
S3 / EC2 / Other Services
```

For applications and workloads, IAM roles are generally preferred over long-term user credentials.

---

## IAM Groups

Groups allow permissions to be assigned to multiple IAM users.

Example:

```text
Developers
│
├── Riko
├── Miko
└── Niko
```

A policy can be attached to the group instead of configuring every user individually.

---

## IAM Roles

An **IAM Role** is an identity that can be assumed by trusted entities.

Roles are commonly used by:

* EC2
* Lambda
* ECS
* EKS
* AWS services
* IAM users
* Federated identities

Example:

```text
EC2
 ↓
IAM Role
 ↓
Temporary Credentials
 ↓
S3
```

Roles provide temporary credentials rather than requiring applications to store long-term access keys.

---

# IAM Policies

An IAM policy defines what an identity is allowed or denied to do.

Example:

```json
{
  "Effect": "Allow",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::example-bucket/*"
}
```

A policy commonly contains:

```text
Effect
Action
Resource
Condition
Principal
```

### Effect

Defines whether an action is:

```text
Allow
Deny
```

### Action

Defines the API operation.

Example:

```text
s3:GetObject
ec2:DescribeInstances
iam:ListUsers
```

### Resource

Defines which AWS resource the policy applies to.

### Condition

Adds additional requirements.

Example:

```text
IP address
Region
MFA
Tags
Time
```

### Explicit Deny

An explicit `Deny` generally overrides an `Allow`.

Simplified model:

```text
Explicit Deny
      ↓
   DENIED

No Allow
      ↓
   DENIED

Allow
      ↓
  ALLOWED
```

# ARN

An **Amazon Resource Name (ARN)** uniquely identifies AWS resources.

General structure:

```text
arn:partition:service:region:account-id:resource
```

Example:

```text
arn:aws:s3:::example-bucket
```

ARNs are frequently used inside IAM policies.

An EC2 instance can run:

* Linux
* Windows
* Applications
* Web servers
* Databases
* Security tools

Basic architecture:

```text
Internet
   ↓
VPC
   ↓
Subnet
   ↓
EC2 Instance
```

## EC2 Instance

Important configuration includes:

```text
AMI
Instance Type
Storage
Network Interface
Security Group
IAM Role

Subnet
```

### AMI

* Operating system
* Applications
* Configuration
* Packages

---

## Instance Types

Common resource categories include:

```text
General Purpose

```

# EBS

**Elastic Block Store (EBS)** provides persistent block storage for EC2.

```text
EC2
 ↓
EBS Volume
```

EBS volumes can contain:

* Operating system
* Applications
* Databases
* Files

# S3

**Amazon S3 (Simple Storage Service)** provides object storage.

S3 stores data inside:

```text
Bucket
  ↓
Objects
```

Example:

```text
my-bucket
│
├── images/
│   ├── logo.png
│   └── photo.jpg
│
└── backups/
    └── database.zip
```

---

## S3 Objects

An S3 object consists of:

```text
Key
Data
Metadata
```

Example:

```text
Key:
images/logo.png
```

## S3 Bucket

Bucket access can be controlled through:

* IAM policies
* Bucket policies
* ACLs
* Block Public Access
* Access Points
* Conditions

Publicly exposed buckets can lead to serious data exposure.

# VPC

**Amazon Virtual Private Cloud (VPC)** provides an isolated virtual network in AWS.

Basic structure:

```text
VPC
│
├── Public Subnet
│
├── Private Subnet
│
└── Database Subnet
```

A VPC contains resources such as:

* Subnets
* Route tables
* Internet gateways
* NAT gateways
* Security groups
* Network ACLs

---

# CIDR

CIDR notation defines IP address ranges.

Example:

```text
10.0.0.0/16
```

A VPC might use:

```text
10.0.0.0/16
```

With subnets:

```text
10.0.1.0/24
10.0.2.0/24
10.0.3.0/24
```

---

# Subnets

A subnet is a range of IP addresses inside a VPC.

Subnets are associated with a single Availability Zone.

Example:

```text
VPC: 10.0.0.0/16
│
├── Public Subnet
│   └── 10.0.1.0/24
│
└── Private Subnet
    └── 10.0.2.0/24
```

---

# Public and Private Subnets

A **public subnet** generally has a route to an Internet Gateway.

```text
Internet
   ↓
Internet Gateway
   ↓
Public Subnet
   ↓
EC2
```

A **private subnet** does not have a direct route to the internet.

Outbound internet access can commonly use a NAT Gateway.

```text
Private Subnet
      ↓
 NAT Gateway
      ↓
Internet Gateway
      ↓
 Internet
```

---

# Internet Gateway

An **Internet Gateway (IGW)** allows communication between a VPC and the internet when routing and public addressing are configured appropriately.

```text
VPC
 ↓
Internet Gateway
 ↓
Internet
```

---

# NAT Gateway

A **NAT Gateway** allows resources in private subnets to initiate outbound connections to the internet without making those resources directly reachable from the internet.

```text
Private EC2
    ↓
NAT Gateway
    ↓
Internet Gateway
    ↓
Internet
```

---

# Route Tables

Route tables determine where network traffic is sent.

Example:

```text
Destination       Target
0.0.0.0/0         Internet Gateway
10.0.0.0/16       local
```

Private subnet example:

```text
Destination       Target
0.0.0.0/0         NAT Gateway
10.0.0.0/16       local
```

---

# Security Groups

A **Security Group** acts as a virtual firewall for AWS resources such as EC2.

Security groups are:

* Stateful
* Associated with network interfaces
* Based on allow rules

Example:

```text
Inbound
22   → SSH
80   → HTTP
443  → HTTPS
```

A security group does not use explicit deny rules.

---

# Network ACLs

A **Network Access Control List (NACL)** controls traffic at the subnet level.

NACLs are:

* Stateless
* Associated with subnets
* Based on allow and deny rules
* Evaluated using rule numbers

Simplified comparison:

```text
Security Group
→ Resource level
→ Stateful
→ Allow rules

NACL
→ Subnet level
→ Stateless
→ Allow + Deny
```

# VPC Peering

VPC Peering allows two VPCs to communicate privately.

```text
VPC A

  │ Peering
```

# Transit Gateway

```text

       VPC A    VPC B    VPC C
```

It is commonly used for larger AWS environments.

# AWS Shared Responsibility Model

AWS security follows a **shared responsibility model**.

```text
AWS
│
└── Security OF the Cloud

Customer
│
└── Security IN the Cloud
```

AWS is responsible for the underlying infrastructure.

Customers are responsible for security configuration and data within their AWS environment, depending on the service.

Examples of customer responsibilities include:

* IAM permissions
* Data
* Application security
* Network configuration
* Operating system configuration on applicable services
* Encryption configuration
